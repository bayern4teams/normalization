**Scope:** an internal FastAPI + React app that (1) must answer only to localhost and the private local network, and (2) must refuse to connect to a user-defined Postgres or ClickHouse target whose address is outside the local network. Outbound internet in general is out of scope. Research only; nothing was changed in the repo.

## 1. Binding, Docker publishing and host firewalls (9)

1. Uvicorn — Settings — https://uvicorn.dev/settings/ — `--host` default 127.0.0.1; 0.0.0.0 reaches the LAN. `--proxy-headers` is on by default and trusts forwarded headers only from `--forwarded-allow-ips` (default localhost).
2. Uvicorn source — `proxy_headers.py` — https://github.com/encode/uvicorn/blob/master/uvicorn/middleware/proxy_headers.py — applies `trusted_hosts` to the connecting address; reads `X-Forwarded-For` right to left and takes the first untrusted entry.
3. Docker — Port publishing and mapping — https://docs.docker.com/engine/network/port-publishing/ — no host address means all host interfaces; 127.0.0.1 or ::1 limits access to the Docker host. The page warns publishing is insecure by default.
4. Docker — Packet filtering and firewalls — https://docs.docker.com/engine/network/packet-filtering-firewalls/ — says Docker and ufw are incompatible: published-port traffic is diverted in the `nat` table before ufw's INPUT chain, so the firewall is effectively ignored. Does not mention DOCKER-USER (page text as fetched).
5. Docker Compose — Define services (ports) — https://docs.docker.com/reference/compose-file/services/ — `"127.0.0.1:8001:8001"` limits the interface; omitting the host IP binds all interfaces and can bypass host firewall rules.
6. Docker — Bridge network driver — https://docs.docker.com/engine/network/drivers/bridge/ — default gateway mode is `nat`; cross-network traffic only via published ports; host binding defaults to all addresses unless set.
7. Docker Engine 28 release notes — https://docs.docker.com/engine/release-notes/28/ — 28.0.0 fixed neighbouring hosts reaching ports mapped to loopback; 28.3.3 fixed CVE-2025-54388; `allow-direct-routing` and `DOCKER_INSECURE_NO_IPTABLES_RAW` re-open those paths. Loopback publishing is not safe on old engines.
8. GitHub advisory — Moby firewalld reload (CVE-2025-54388) — https://github.com/advisories/GHSA-x4rx-4gw3-53p4 — Engine 28.2.0 to 28.3.2: after a firewalld reload a remote host with a route to the bridge could reach published ports, even loopback-only ones. Fixed in 28.3.3.
9. `chaifeng/ufw-docker` — https://github.com/chaifeng/ufw-docker — fixes the ufw bypass with rules in `/etc/ufw/after.rules` on the DOCKER-USER chain; GPL-3.0 (copyleft: ask before copying code); last-commit date not shown on the page.

## 2. Private address ranges and Python semantics (14)

10. RFC 1918 — Address Allocation for Private Internets — https://www.rfc-editor.org/rfc/rfc1918 — 10/8, 172.16/12, 192.168/16.
11. RFC 4193 — Unique Local IPv6 Unicast Addresses — https://www.rfc-editor.org/rfc/rfc4193 — fc00::/7, L bit 1 for local assignment; site-edge devices should keep such packets from leaving the site.
12. RFC 6890 — Special-Purpose IP Address Registries — https://www.rfc-editor.org/rfc/rfc6890 — defines the Forwardable and Globally Reachable columns that Python's `is_global` follows.
13. IANA — IPv4 Special-Purpose Address Space — https://www.iana.org/assignments/iana-ipv4-special-registry/iana-ipv4-special-registry.xhtml — Globally Reachable = False rows include 0.0.0.0/8, 127.0.0.0/8, 192.0.0.0/24 (with exceptions), 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24, 240.0.0.0/4. The page extract did not list RFC 1918, 169.254/16 or 100.64/10 in that set; check the live table before coding a list.
14. IANA — IPv6 Special-Purpose Address Space — https://www.iana.org/assignments/iana-ipv6-special-registry/iana-ipv6-special-registry.xhtml — Globally Reachable = False includes ::1, ::, ::ffff:0:0/96 (IPv4-mapped), 100::/64, 2001:db8::/32, fc00::/7, fe80::/10, and others.
15. RFC 6598 — IANA-Reserved IPv4 Prefix for Shared Address Space — https://www.rfc-editor.org/rfc/rfc6598 — 100.64.0.0/10 for carrier-grade NAT links; not globally routable but distinct from RFC 1918, not to be forwarded across provider boundaries.
16. Tailscale — What are these 100.x.y.z addresses? — https://tailscale.com/kb/1015/100.x-addresses — Tailscale assigns each device an address from 100.64.0.0/10, so a Tailscale VPN peer looks like a CGNAT address (owner decision, section "Edge cases").
17. RFC 3927 — Dynamic Configuration of IPv4 Link-Local Addresses — https://www.rfc-editor.org/rfc/rfc3927 — 169.254.0.0/16; routers must not forward such packets.
18. RFC 4291 — IPv6 Addressing Architecture — https://www.rfc-editor.org/rfc/rfc4291 — section 2.5.5.2: IPv4-mapped form is 80 zero bits, FFFF, then the IPv4 address (`::FFFF:129.144.52.38`).
19. Python — `ipaddress` module — https://docs.python.org/3/library/ipaddress.html — `is_private` = not globally reachable per the IANA registries, opposite of `is_global` except 100.64/10 where both are False; IPv4-mapped IPv6 follows the embedded IPv4; 3.13 changes listed (192.0.0.0/24, 64:ff9b:1::/48, 2002::/16).
20. Python — What's New in 3.13 — https://docs.python.org/3/whatsnew/3.13.html — `is_global` and `is_private` fixed for address and network classes; adds `IPv4Address.ipv6_mapped`. Only the first 100000 characters were read.
21. CPython issue 113171 — https://github.com/python/cpython/issues/113171 — the old private-network list was wrong both ways (some special ranges treated as global, some broad ranges hiding global subnets); fix PR 113179 was backported; 100.64/10 needed separate handling. Result: the same address can classify differently across Python patch versions, so pin the Python version and add a test with an explicit list.
22. Python — `socket` module — https://docs.python.org/3/library/socket.html — `getaddrinfo` returns a list of tuples, callers try them in order; `AI_NUMERICHOST` disables name resolution; `inet_aton` accepts short forms and its acceptance depends on the C library. Only the first 100000 characters were read.
23. WHATWG — URL Standard — https://url.spec.whatwg.org/ — the IPv4 parser accepts decimal, octal (leading 0) and hex (0x) parts and short forms, so `2130706433`, `0177.0.0.1` and `0x7f.1` all mean 127.0.0.1. Only the first 100000 characters were read.

## 3. Request-side guards: Host, CORS, CSRF, proxies (10)

24. Starlette — Middleware — https://starlette.dev/middleware/ — `TrustedHostMiddleware` returns 400 when the Host header is not in `allowed_hosts` (wildcards allowed); `CORSMiddleware` cannot use credentials with wildcard lists.
25. Starlette source — `trustedhost.py` — https://github.com/encode/starlette/blob/master/starlette/middleware/trustedhost.py — parses the Host header, drops the port, lowercases, matches exact or by `*.` suffix; 400 "Invalid host header" otherwise. Matches names only; there is no CIDR support.
26. FastAPI — Behind a Proxy — https://fastapi.tiangolo.com/advanced/behind-a-proxy/ — forwarded headers are ignored by default for security; trusting `"*"` trusts every sender, so restrict `--forwarded-allow-ips` to the proxy.
27. MDN — X-Forwarded-For — https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/X-Forwarded-For — spoofable; if the server is directly reachable, no part of the list is trustworthy; count from the right or skip trusted proxies.
28. RFC 9110 — HTTP Semantics — https://www.rfc-editor.org/rfc/rfc9110 — defines the Host field (section 7.2) and misdirected requests (7.4). The 7.2 text itself was not read (page truncated); cite the section number only.
29. MDN — CORS — https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS — browser-enforced; simple requests still reach the server and are processed, the browser only withholds the response. CORS is therefore not an access control.
30. OWASP — CSRF Prevention Cheat Sheet — https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html — custom headers force a preflight; verify Origin/Referer; reject "simple" content types such as text/plain on JSON APIs.
31. Django — Settings (`ALLOWED_HOSTS`) — https://docs.djangoproject.com/en/stable/ref/settings/ — a Host-header allowlist as a framework default; with DEBUG and an empty list it allows `.localhost`, `127.0.0.1`, `[::1]`. Only the first 100000 characters were read.
32. Superset — Configuring Superset — https://superset.apache.org/admin-docs/configuration/configuring-superset — no setting restricting database hosts found on the page; `ENABLE_PROXY_FIX` is the only proxy-related knob shown (a "not found" result, kept as field evidence).
33. Grafana — Configure Grafana — https://grafana.com/docs/grafana/latest/setup-grafana/configure-grafana/ — `http_addr` empty = all interfaces; `enforce_domain` redirects when Host differs (anti-rebinding); `data_source_proxy_whitelist` limits data source URLs but not PostgreSQL, MySQL or MSSQL sources. Only the first 100000 characters were read.

## 4. DNS rebinding and local-service defence (12)

34. Wikipedia — DNS rebinding — https://en.wikipedia.org/wiki/DNS_rebinding — attack flow; defences listed: filter private and loopback answers at DNS or firewall, browser DNS pinning, reject unknown Host headers.
35. MCP specification 2025-06-18 — Transports — https://modelcontextprotocol.io/specification/2025-06-18/basic/transports — Streamable HTTP servers MUST validate `Origin` against DNS rebinding, SHOULD bind to 127.0.0.1 not 0.0.0.0, SHOULD authenticate.
36. MCP — Security Best Practices — https://modelcontextprotocol.io/specification/2025-06-18/basic/security_best_practices — SSRF section: block RFC 1918, loopback, link-local, fc00::/7, fe80::/10; "avoid implementing IP validation manually" (octal, hex, IPv4-mapped tricks); pin DNS between check and use; names Smokescreen. Local-server section: use stdio or unix sockets or a token.
37. Jupyter Server — Config options — https://jupyter-server.readthedocs.io/en/latest/other/full-config.html — `ip` defaults to localhost; `allow_remote_access` False means a Host header naming a non-local domain gets 403 (anti-rebinding); `local_hostnames` extends the local set.
38. webpack — DevServer (`allowedHosts`) — https://webpack.js.org/configuration/dev-server/ — `'auto'` allows localhost and configured hosts; `'all'` is not recommended because it opens DNS rebinding.
39. Vite — Server options — https://vite.dev/config/server-options — `server.host` default localhost; `allowedHosts` defaults to localhost, `.localhost` and IP addresses; `true` lets any site rebind. Relevant to the React UI served by `vite` or `vite preview` in `ui/`.
40. GitHub advisory — Vite GHSA-vg6x-rcgg-rjx6 (CVE-2025-24010) — https://github.com/vitejs/vite/security/advisories/GHSA-vg6x-rcgg-rjx6 — Jan 2025: permissive CORS, no WebSocket Origin check and no Host check let any website read dev-server responses even when run only on localhost. 41. NCC Group — Ollama DNS rebinding (CVE-2024-28224) — https://www.nccgroup.com/research/technical-advisory-ollama-dns-rebinding-attack-cve-2024-28224/ — a malicious page used rebinding to reach the unauthenticated local API and exfiltrate files; fixed in v0.1.29.
42. GitHub advisory — Ollama GHSA-5jx5-hqx5-2vrj — https://github.com/advisories/GHSA-5jx5-hqx5-2vrj — published 8 Apr 2024; versions before 0.1.29.
43. WICG — Private Network Access — https://wicg.github.io/private-network-access/ — Draft Community Group Report (26 Sep 2024), not a standard: CORS preflight for public-to-private requests via `Access-Control-Request-Private-Network`.

## 5. Refusing non-local database targets (egress guard) (8)

46. OWASP — SSRF Prevention Cheat Sheet — https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html — "Deny-lists are bypass-prone. Prefer allow-lists." ## Current state (from the code)

- **API bind.** `packages/normapi/src/normapi/main.py` runs `uvicorn.run(host=os.environ.get("NORM_API_HOST", "0.0.0.0"))` with an inline "intentional: container-facing" comment. `packages/normapi/Dockerfile` CMD is `uvicorn normapi.main:app --host 0.0.0.0 --port 8080`. No `--forwarded-allow-ips` or `--proxy-headers` flag is set, so uvicorn defaults apply (entry 1).
- **Compose publishing.** `compose.yaml` publishes every port without a host IP, so all bind 0.0.0.0 on the host: `api` `"8080:8080"`, `libpostal` `"8081:8081"`, `postgres` `"5535:5432"` (password `normalization`), and the demo containers `demo-postgres` `"5434:5432"`, `demo-mysql` `"3307:3306"`, `demo-mongo` `"27018:27017"`, `demo-clickhouse` `"8124:8123"`. Per entries 3, 4, 5, a ufw INPUT rule would not stop these. `compose.yaml` also commits a fixed `NORM_SECRET_KEY` for the connection-password encryption.
- **Other services.** No Marquez service exists in compose. Lineage goes out only if `NORM_OPENLINEAGE_URL` is set (`normapi/lineage.py::_forward`, any `http(s)://` URL, no address check). There is no compose service, Dockerfile or nginx for the UI: `ui/` runs through `vite` (dev, port 5173) or `vite preview` (port 4173, per `ui/playwright.config.ts`). `ui/vite.config.ts` sets no `server.host` or `allowedHosts`, so Vite defaults apply (entry 39). The UI calls the API at `VITE_API_BASE_URL` or `http://localhost:8080` (`ui/src/api/client.ts`).
- **CORS.** `normapi/app.py::create_app` adds `CORSMiddleware` with `allow_origins` = four localhost/127.0.0.1 origins on ports 5173 and 4173 plus `NORM_CORS_ORIGINS`, and `allow_methods=["*"]`, `allow_headers=["*"]`. CORS does not stop non-browser callers or simple cross-origin requests (entry 29).
- **No caller or Host check.** A grep of `packages` finds no `TrustedHostMiddleware`, no `request.client` check, no auth dependency, no `X-Forwarded` handling. The only `ipaddress` use is `normalizers/url.py` (a value normalizer, unrelated). Any host that can reach port 8080 can call every route.
- **Connection host validation: none.** `ConnectionCreateRequest.host` in `normapi/schemas.py` is a plain `str`; `engine` is `Literal["postgres", "clickhouse"]`. `routes.py::create_connection` stores it via `PgPersistence.save_connection`. `routes.py::_resolve_connection` accepts an `adhoc` inline host with no check. Nothing resolves the hostname.
- **Where the host is used.** All routes and jobs go through two shared builders in `normapi/clone_executor.py`: `build_source_connector` (called from `routes.py` discovery routes and four places in `clone_executor.py`) and `build_destination_writer` (two places). Postgres gets an f-string DSN `postgresql://{user}:{password}@{host}:{port}/{database}` with no URL-encoding, so a crafted host or password can change the parsed target (entries 48, 49). ClickHouse passes `host` and `port` to `clickhouse_connect.get_client` in `normio/connectors/clickhouse.py::ClickHouseConnector`. A check at these two builders covers every path, but it must run at save time too, for a clear error.
- **Container effect.** Inside the `api` container, `localhost` is the container, and compose service names (`postgres`, `demo-postgres`) resolve to Docker bridge addresses (private). The default `NORM_PG_DSN` points at the `postgres` service name, so a "private only" rule must accept bridge-network addresses.

## Defence layers seen in the field

Each layer is independent; none is chosen here.

- **A. Bind to loopback or to one LAN interface.** Uvicorn `--host` (1), compose `"127.0.0.1:8080:8080"` (3, 5), Vite `server.host` (39), Jupyter `ip` (37), MCP "bind localhost" (35), Postgres `listen_addresses` (field notes). Pros: removes the attack surface before any code runs. Cons: loopback excludes the LAN, and one chosen interface IP can change under DHCP; Docker releases before 28.0 / 28.3.3 leaked loopback-published ports to neighbours (7, 8); needs a reachable-from-LAN test.
- **B. Host-level firewall on the DOCKER-USER chain.** (4, 9). Pros: filters by source CIDR for all containers, including libpostal and the demo databases. Cons: outside the repo, so the project rule B10 (changes go through a committed file) needs a committed script; ufw-docker is GPL-3.0 (ask first); Docker versions differ (7).
- **C. Source-address check in the app.** Reject any caller whose peer address is outside the allowed set, using `ipaddress` (19-21) in a small ASGI middleware. Pros: works wherever uvicorn is bound; one place. Cons: behind NAT or the Docker userland proxy the peer may be the bridge gateway, not the real client; trusting `X-Forwarded-For` is spoofable (2, 26, 27); Python classification changed across versions (20, 21).
- **D. Host-header allowlist.** Starlette `TrustedHostMiddleware` (24, 25), Jupyter `allow_remote_access` (37), Django `ALLOWED_HOSTS` (31), webpack/Vite `allowedHosts` (38, 39), Grafana `enforce_domain` (33). Pros: stops DNS rebinding from a browser (34, 40, 41). Cons: names only, no CIDR; every legitimate LAN name or IP the users type must be listed (the Vite default already admits any IP literal); not an access control for direct callers.
- **E. Origin validation and tighter CORS.** MCP Origin rule (35), Vite advisory (40), CORS and CSRF notes (29, 30). Pros: closes cross-site and WebSocket hijack paths. Cons: only affects browsers; current CORS already lists fixed origins, so the gap is `allow_methods/allow_headers="*"` plus no Origin check on non-preflighted requests.
- **F. Browser-side Local Network Access.** (43, 45). Pros: no code. Cons: draft, browser-specific, not enforceable server-side; not a defence to rely on.
- **G. Resolve, check, then connect to the validated IP.** OWASP (46), MCP (36), PortSwigger bypass list (47). Pros: closes the "name resolves to a public IP" case and the check-then-reconnect race. Cons: needs a per-driver pin: libpq `hostaddr` (48) is documented; the clickhouse-connect pinning option is not confirmed (50, 51), so it may need a custom connection pool or a check on the resolved socket address after connect.
- **H. Strict address parsing before any DNS.** Parse the literal with `ipaddress` / `getaddrinfo(AI_NUMERICHOST)` (19, 22), reject decimal/octal/hex forms (23, 47), unwrap `::ffff:` (18, 19). Pros: cheap, closes encoding bypasses. Cons: needs a decision for short forms the OS resolver might accept (22).
- **I. Allowlist of networks (and optional names) set by the deployer.** n8n (54), OpenProject (55), Portkey (56): all three keep the list in environment or deployment config, not in the UI, and apply the check to the resolved IP. Pros: the deployer can narrow "private" to the real site subnet. Cons: our direction is inverted (they block private; we allow only private), so only the structure carries over.
- **J. Network-level egress control.** Container network with no default route, an `internal: true` network, or an egress proxy (53, 36). Pros: holds even if the app code has a bug. Cons: a committed compose change; Smokescreen blocks private targets by default, which is the wrong direction without custom ACLs; libraries such as Advocate (52) are archived and HTTP-only.
- **K. Parse, don't concatenate.** Build the Postgres DSN with a structured API (49) instead of an f-string. Pros: removes host/port injection and multi-host strings. Cons: touches `build_source_connector` and `build_destination_writer` and their tests.

## Edge cases to decide

- **IPv6 ULA (`fc00::/7`).** Private per RFC 4193 (11) and `is_private` (19). Decide: allow, and does the UI/API bind IPv6 at all (pgAdmin binds `[::]` by default, field notes)?
- **CGNAT `100.64.0.0/10`.** Both `is_private` and `is_global` are False (19). Tailscale uses it (16); a carrier may also put an ISP gateway there (15). Decide whether the VPN counts as "local network"; `is_private` alone will not answer this.
- **Link-local (`169.254/16`, `fe80::/10`).** Not routable (17); includes cloud metadata 169.254.169.254 (36). IPv6 link-local needs a zone id (scope) which `ipaddress` handles from 3.9. Decide: allow for LAN or refuse.
- **Loopback and "this machine".** 127.0.0.0/8 and `::1`. From inside the `api` container, "localhost" is the container, not the host. `host.docker.internal` / bridge gateway is a separate decision.
- **Docker bridge and compose names.** Service names resolve to private bridge addresses (a CIDR like 172.16/12). Allowed by the private rule; confirm the Docker default pool is not changed on the machine.
- **Unix sockets.** libpq treats a `host` starting with `/` as a socket directory (48). The current model has `host: str`; decide whether to refuse such values (probable) or allow only specific paths.
- **Multi-host strings.** libpq accepts comma-separated host lists (48). With an f-string DSN a value like `a,b` is a real attack (K). Decide whether a host must be exactly one address.
- **Hostnames resolving to several IPs.** `getaddrinfo` returns a list (22). Decide: every address must be private (strict, matches OpenProject, 55), or the first. Also decide whether to refuse a name whose answers mix private and public.
- **IPv4-mapped IPv6 (`::ffff:a.b.c.d`).** Follows the embedded IPv4 in `ipaddress` (19) and is Globally Reachable = False in the registry (14); decide whether to unwrap or refuse the form entirely.
- **Encoded IPv4 (`2130706433`, `0177.0.0.1`).** Accepted by WHATWG and by some libc resolvers (22, 23); decide to reject non-dotted-decimal literals outright.
- **VPN-assigned addresses.** WireGuard/OpenVPN/Tailscale ranges can be any private block or CGNAT; the allowlist needs a deployer-set override (I).
- **Name resolution timing.** Check at save time, at every connect, or both: a DNS answer can change after save (46, 36). Saved connections also persist across restarts, so a record made before the rule exists must be re-checked at use time.
- **The lineage URL.** `NORM_OPENLINEAGE_URL` is an outbound HTTP destination set by the deployer. Out of scope per the brief, but it is the same class of check; flag for the owner.
- **Python version.** `is_private` results differ before and after the 3.13 fix and its backports (20, 21); pin the version and test against a fixed table.
