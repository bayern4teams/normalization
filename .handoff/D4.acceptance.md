## Ambiguity decisions (flag if wrong)
- `hint` is only required to be None or a `MissingKind`; no specific kind is demanded per sentinel (a hint is not truth).
- FREE_TEXT/UNKNOWN abstain: `GenericTextNormalizer.validate("N/A")` is False today, so a naive "fails the validator" rule WOULD report it; the plan's `_discriminates` logic says no. Kept in its own class (TestUntypedAbstains) so the lead can overrule one decision without touching the rest.
- "Small recurring set": a column where every value fails, and distinct junk each seen once, report nothing. Boundaries (what share, what count) are deliberately NOT tested; the worker must derive or `ponytail:`-note them.
- `NA` is VALID for DATE in `DateNormalizer.validate` today (True), so no test expects `NA` reported in a date column.
- Count-0 entries count as absent. Sentinels are matched verbatim (no strip, no casefold merging).
- Grep exemption: a `ponytail:` / "deriv" comment covers the code block right after it (until a blank line). Quoted `"-"` as e.g. a split separator is flagged; the worker adds a `ponytail:` note or avoids the literal.
- The attacker should still try: unicode sentinels (`—`, NBSP), huge cardinality (1e6 distinct), keys with `None`/non-str, bool counts, negative counts, PHONE/EMAIL/URL columns with `n/a`, DATETIME, type given as lowercase name, the ptype-path import being optional (module must import without ptype).
