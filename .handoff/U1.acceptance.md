# U1 acceptance (derive) - the new UI

Source: `docs/improvement-report.md` "U1 - Replace the UI" (quoted as *U1*), owner decisions R5-R8,
R10, R18-R23, plan 2.4, 2.6, 2.9, 4, 5, 9 (U1), ADR-023. Written before any U1 implementation
existed. Existing API code was read only to build test fixtures (how a queue entry is created).

Run the Python half (file names contain a dot, so importlib mode; move both to `tests/unit/` when
implementing, e.g. `test_u1_review_route.py`, `test_u1_serving.py`):

    ( ulimit -v 16777216; uv run pytest -p no:cacheprovider --import-mode=importlib -q \
        .handoff/U1.test_review_route.py .handoff/U1.test_serving.py )

Result on the current code (2026-10-28): **32 failed, 1 passed**. The one pass is a control
(`test_no_telemetry_package_in_the_dependency_lock`). Failure reasons were read: `{"detail":"Not
Found"}` for the review route; "precondition: the review route returns the raw value" for the masking
cases; `ui/dist/index.html is missing`; `@mantine/core missing`; old pages/specs still present;
`access-control-allow-origin` present; `cdn.jsdelivr.net`, `fonts.googleapis.com` and
`fastapi.tiangolo.com` in the `/docs` and `/redoc` HTML. All are the missing behaviour, none an import
or fixture error. Both files pass `ruff check` and `ruff format`.

Validation of the tests themselves: with a throw-away route that returns raw entries, all 18 review
tests pass; with `routes.safe_preview` replaced by the identity, the masking cases for `queue_list`,
`queue_entry`, `job_errors` and `verdict_response` fail (the masking checks bite). With a fake
`ui/dist` and local docs assets, all serving tests pass.

## THE LEAD SETS (one place each)

| Constant | File | Meaning |
|---|---|---|
| `REVIEW_LIST_ROUTE`, `REVIEW_ENTRY_ROUTE` | `U1.test_review_route.py` | GET paths of the review route (whole pending list, no paging; one entry by queue key). Defaults are placeholders. |
| `UI_DIST_ENV` | `U1.test_serving.py` | Name of the env var `app.py` reads for the UI directory, or `None` if it finds `ui/dist` itself. |

Entries are found by the field the report names, `occurrences`; the raw value is any string leaf
equal to the planted value; a reading is an ISO date string or a `{year,month,day}` object. No other
field name is assumed.

## Open questions for the lead (A1: I did not pick a reading)

1. **Accept without a pre-selected reading.** If no reading is pre-selected, what does the accept
   key accept? (a) readings get number keys 1..n, accept = pick one; (b) accept applies to a
   highlighted reading. F3 and F5 are written to hold for either; confirm.
2. **Keep ambiguous and undo have no API today.** Verdicts are append-only and accept only a clean
   decided value (ADR-018). Where is "keep ambiguous" stored (a verdict kind?) and how does undo
   work (a revoking verdict?). I wrote no API test for either so as not to invent a contract; add one
   when you decide (a "keep ambiguous" decision must not change the cell and must survive a rerun).
3. **Other routes that echo the value.** `POST /preview` and `/field-test` return `original`,
   `display` and unmasked `structured.candidates` for the value the caller sent (observed on the
   current app), and `/runs/{id}/values` returns stored caller values. R23 says every other response
   stays masked, R19 says those routes stay. The `trace` case therefore checks the trace list only.
   Rule on whether these are in R23's scope; if yes, add them to check 5.
4. **Runs / Run detail / Comparison pages.** Not named in R19, not among the five screens; check 13
   (`test_pages_outside_the_five_screens_are_not_rebuilt`) requires them gone (ADR: "Pages not in the
   list above are not rebuilt"). Drop that test if you rule otherwise.
5. `/redoc` is not named by the report; check 9 requires it off or local (the "no CDN, no web fonts"
   rule covers the app). Drop `test_redoc_is_off_or_local` if you rule it out.
