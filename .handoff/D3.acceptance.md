## Assumed API (kept minimal; everything else is introspected)
- Seam: `clone_executor._run_phase2(persistence, dispatcher, None, job_id)` on SQLite `PgPersistence`, `build_source_connector` / `build_destination_writer` / `_make_pool` monkeypatched, a hand-built job record with `destination_plan` from `plan_one_table`. Fakes: source has `get_columns` (ColumnInfo), `get_primary_key`, `read_table`, `close`; dest has `bulk_insert`, `close`. So lineage must read the columns from `source.get_columns(table)` and companions from the job's `destination_plan` (`currency_columns`, `code_columns`), not from rows.
- `GET /normalization/clone-jobs/{job_id}/lineage`: 200 with a list of events (or an object wrapping exactly one list); 404 for an unknown job; 200 `[]` for a job with no events.
- Table `normalization_lineage_events` created by `ensure_schema()` on SQLite too (portable DDL). Read by raw `SELECT *`; the payload column is found by decoding every cell (JSON string or dict containing `eventType`). Names of persistence methods are NOT assumed.
- Events: RunEvent per (job, table): one `runId` per table shared by START and its COMPLETE/FAIL; `inputs` = 1 dataset whose namespace+name contains the source database and ends in the table; `outputs` = 1 dataset containing the destination database and ending in the table; the job id appears in every event; `schemaURL` pinned to core 2-0-2.
- `columnLineage` is under `outputs[0].facets.columnLineage` (the spec's dataset-facet slot), on every COMPLETE; `fields[dest_col].inputFields` has exactly one entry `{namespace, name, field}` equal to the input dataset and the source column (companion maps to its base column). Transformation text: every string in the entry other than namespace/name/field must contain the normalizer name (`registry.require(type).name`), the semantic type and `SCAFFOLD_PROFILE.version` as tokens. Format is free (`transformations[].description`, `transformationDescription`, ...).
- Facet `_schemaURL` under openlineage.io/spec/facets must be a vendored schema; custom facets only need `_producer`/`_schemaURL`.
- Companion suffix is `_currency`/`_code` (single underscore, `clone_executor._CURRENCY_SUFFIX/_CODE_SUFFIX`), not `__currency`/`__code` as the brief says; the test reads them from the plan.

## Satisfiability and sensitivity
A scratch reference implementation outside the repo (`.../scratchpad/ref/refd3.py`, pytest plugin: wraps `_normalize_table`, adds table, route, forwarding) passes 34/36 (the 2 left need `lineage.py` to exist; the grep function run on that source returns clean). Four mutations of the reference were each caught: companion columns dropped, hard-coded profile version, duplicate COMPLETE, input dataset == output dataset.

## Flags for the lead
1. Brief says `__currency`/`__code`; the code uses `_currency`/`_code`. Tests follow the code.
2. Plan says "columnLineage output facet"; the spec puts it in the dataset `facets` slot (what Marquez reads), not `outputFacets`. Tests require `facets`.
3. Username counts as a credential (must not appear). The host is allowed (a namespace like `postgres://host:5432` is normal OpenLineage); say if you want the host banned too.
4. The failure-text test (exception message echoing the DSN must not reach a FAIL payload) is stricter than the report's wording; relax or drop `test_a_failure_message_that_echoes_...` if you disagree. It pins that FAIL carries at most a redacted message.
5. Per-table events are assumed (one run per job and table, as the plan says). A job-level event with no datasets is tolerated by most tests but counts in `test_every_event_belongs...` (expects exactly 4 events for 2 tables).
6. Not asserted: a hanging forwarding endpoint (needs a timeout value; add once chosen), in-place mode (output = staging name), typed destination (D5), events on a failure before the first table.
7. `test_no_new_runtime_dependency...` fails if `openlineage` is added to pyproject/uv.lock; delete it if you take `openlineage-python` after `check_licenses.py`.
