## Field names the worker MUST match (library-independent)
- `structured["phonetic"]` (existing dict): legacy keys `soundex`,`nysiis`,`metaphone`,`match_rating_codex` ONLY for
  Latin-script input; new keys `double_metaphone`, `beider_morse` (non-empty `str` or `list[str]` of alternatives;
  `|`/whitespace inside a string also separates alternatives). Sharing = same key, >=1 common code.
- `structured["phonetic_status"] == "not_applicable"` and `structured["script"]` (ISO 15924 long name or 4-letter code,
  case-insensitive: Cyrillic, Arabic, Han, Hangul, Greek, Hebrew, Devanagari, Thai) on EVERY non-Latin / mixed input.
  The status refers to the Anglo-centric keys: Cyrillic and Arabic/Persian input MUST still carry >=1 language-aware key
  (that is how Мухаммед meets Muhammad); Greek/Hebrew may; Han, Hangul, Devanagari, Thai carry NO key at all.
- Latin input: both new keys present, every pre-existing field byte-identical (legacy keys included, `Müller`/`José`
  too: Phase 0 lead decision, script decides, not whether anyascii folded a diacritic). `phonetic_status`/`script` are the
  only other allowed additions.
