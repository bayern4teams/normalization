## Reasons to reject
R1. **Raw values leave outside the review route (R23, ADR-023 "a test asserts that for each").**
 - `GET /clone-jobs/{id}/quality`: `disguised_missing[].value` is the raw column value. Reproduced:
   `_ColumnStats` with 3 failing `03/04/2020` returns `[{'value': '03/04/2020', 'count': 3,...}]`.
   Lead escalated this (HANDOFF "Open escalations", D4 needs the values).
 - NOT escalated: `GET /clone-jobs/{id}/errors`. The column-level finding is built with
   `e.g. {repr(v) for v in stat.samples}` (clone_executor.py ~2253, `"error": "; ".join(findings)`)
   and `routes.get_clone_job_errors` returns `error=row["error"]` unmasked (only `safe_preview` is
   masked). Raw values are therefore in the errors response, and `JobDetailPage.tsx:118` renders
   `{e.error}`, so a raw value can be shown on the Jobs screen (F7). Read from code, not run end to end
   (needs Postgres).
 - The new `GET /clone-jobs` (list) returns every job with its `quality`, so the first leak now comes
   in one call for all jobs.
 - Why the tests pass: the `job_quality` and `job_errors` fixtures never produce a recurring failing
   value or a mistyped column, so those cases are vacuous for this path. Check 5 is "passes", not met.
R2. `/docs` and `/redoc` are switched off, not served locally; the test is parked
 (`.handoff/U1.test_docs_local.md`) and was deleted from `tests/unit/test_u1_serving.py` in the same
 commit that moved it (57d8cbc). Escalated by the lead; report says "serve those assets locally".
R3. Tests changed after derivation without the plan 2.9 form: the /docs test removed (57d8cbc) and
 `JS_NOT_FETCHED` widened (bb162ca) are not `TEST-CHANGE:` commits and carry no `C5:` line; a removed
 test is not allowed by Q15 (only how a test reaches the code). I checked the widening against the
 bundle (all message text, see above), so it is harmless in substance; the form is wrong.
R4. `python3 scripts/check_c5_exceptions.py main` exits non-zero: 11 added `# noqa: E402` /
 `# type: ignore` lines in tests/unit/test_u1_review_route.py (42-49, 474) and test_u1_serving.py
 (33-34) have no C5 comment. guards.yml will be red (AGENTS section 5).

## Smaller findings (not rejecting alone)
- Double send: a decision held, then `pagehide`, then the page unmounts, posts the verdict twice
  (flush in `ReviewPage.tsx` never clears the item's `held` state). Reproduced with a synthetic
  `pagehide` + hash navigation (2 POSTs, expected 1). Verdicts are append-only, same value, so low
  harm; a real tab close does not unmount. A flushed (keepalive) POST that fails (for example 422) is
  swallowed (`.catch(() => undefined)`), so the person is never told that decision was lost.
- Orphans (F6): `ui/src/index.css` (71 lines, classes used nowhere; still imported by main.tsx);
  `ui/README.md` is the Vite template; `ui/playwright.config.ts` header still says "against a REAL
  running normapi" while specs stub the API; unused exports in `api/client.ts`/`types.ts`.
