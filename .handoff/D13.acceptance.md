## Names assumed (existing surface only)

- `normalizers.language.LanguageNormalizer().normalize(value, ctx)`.
- Row evidence = `NormalizationContext.country` (ISO 3166 alpha-2). The clone executor already gives
  every non-COUNTRY column of a row its row country that way (`clone_executor` groups rows by country;
  `_COUNTRY_FROM` lists only the providers). So no new context field is assumed for rows.
- The language code is `NormalizedValue.comparison`: ISO 639-1 where one exists, else ISO 639-3
  (report rows: `ga`, `gaa`, `ukv`, `mn`, `da`).
- AMBIGUOUS result: status `AMBIGUOUS`; `comparison`, `structured["canonical_code"]` and `display`
  must not carry either guessed reading (they may carry the raw input, as POSTCODE does).
- Unit = `FieldSemanticType.QUANTITY`.

## Could NOT derive (needs the lead; the implementer must not guess)

1. **Column evidence (report fix 2, second bullet) has no mechanism to mirror.** `NormalizationContext`
   has `column_date_order` and `column_decimal_mark` (ADR-008/011) and `clone_executor._proven`
   reads only `order` and `mark`; nothing exists for language. The field name, the threshold
   ("how many distinct values prove it") and the rule are the owner's design. No test for
   "a column of 2-letter codes reads `Ga` as `ga`, a column of names as `gaa`". Once a name and shape are
   chosen, add: the code-form column resolves `Ga`->`ga`; the name-form column `Ga`->`gaa`; a mixed column
   states nothing (AMBIGUOUS).
2. **Conflicting evidence (check 6)** only in the weak form: CLDR has no territory listing both readings
   of any collision (computed: 0 of 134), so a row cannot contradict itself. Neither-listed and
   garbage countries are tested. Row-versus-column conflict waits on item 1.
3. **Case rules beyond the report**: the report fixes only exact pycountry spelling (`Ga`, `Mon`).
   `GA`, `ga`, `MON` are not specified. The tests need `ga`, `en`, `eng`, `EN` to stay codes
   (fixed point plus the existing test); whether `GA`/`MON` are AMBIGUOUS is left to the implementer.
4. **The brief says `Kuku-Yalanji` -> `ukv`; pycountry says `gvn`.** `ukv` is the language named `Kuku`, the
   report's "confident and wrong" answer. The test requires `gvn` and refuses `ukv`.
5. **Three names are also well-formed BCP 47 tags**: `Aka-Cari` (Akan + Carian script), `Aka-Bo`
   (Akan + Bolivia), `Uru-Pa-In`. A literal reading of fix 3 would split them to `ak`/`uru`. I required
   own code or AMBIGUOUS (R12, never guess). The lead may relax this to "tag reading allowed" for the
   three, but then the 46-prefix test needs an allowance for them.
6. **Which CLDR statuses count as "lists"**: the tests use every entry Babel's `territory_languages`
   gives (the report's `mnw` in MM/TH has `official_status: None`). An implementation that keeps only
   official languages fails the MM/TH rows, which the report names, so this is not optional.
7. **Whether `display` changes** for an evidence-resolved `Mon`: only `comparison` is asserted.
8. **"Not checked" in the report**: whether CLDR's English name for `gaa` is `Ga`; whether any
   production path feeds a stored `display` back. Not tested.
