   from the payload when unset, "so stored verdict keys and cache keys keep their hashes". The new
   field `column_language_form` is not in that tuple, so a context with no evidence now hashes
   differently for EVERY type. Existing test
   `tests/unit/test_column_evidence.py::TestKeys::test_a_context_without_a_column_order_hashes_as_before`
   fails at e93bc50 (`5b9e834f...` instead of `12bcdc8c...`) and passes at e3eccb8. Effect: stored
   verdict keys and cache keys of all types stop matching (ADR-008/011/014 identity), far beyond
   LANGUAGE. Fix: add `column_language_form` to the `unset` tuple (and keep the test unchanged, L1).
   Why the implementer's own batch missed it: it ran only the three new test files.
2. **Residual confident-wrong answers from the hyphen rule** (report fix 3: "a hyphen splits only a
   valid BCP 47 tag"). `_code_reading` accepts any 5-8 letter piece as a "variant" (Babel parses
   syntactically; the IANA variant registry is not consulted). Measured at e93bc50, all NORMALIZED:
   `Mon-Khmer` -> `mn` (Mongolian), `Ga-Adangme` -> `ga` (Irish), `Mon-Myanmar` -> `mn`,
   `Mon-Burma` -> `mn`, `Ron-Romanian` -> `ro`, `Fas-Persian` -> `fa`. Same class as
   `Kuku-Yalanji` -> `Kuku`. None of these is a pycountry name, so the sweep over 7,910 names
   cannot see them. Not new (parent gave the same for these six) but fix 3 is not met for
   free text. No test covers it.
