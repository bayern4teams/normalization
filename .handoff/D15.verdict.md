Branch feat/round2-fixes at 8a35d15. Scope: local network only (ADR-022). No source or test edited.
The address set itself held. REJECT is for one functional break of the LAN use case, three
untested wiring points and two small defects (below).

## Defects (why REJECT)
1. **LAN access is broken under compose (functional, Q-B).** `compose.yaml` api service has no
   `env_file` and its `environment:` lacks `NORM_BIND_ADDR`, `NORM_ALLOWED_HOSTS`,
   `NORM_ALLOWED_NETWORKS`. Compose uses `.env` only for substitution, so the container never sees
   them: a LAN caller using `http://<NORM_BIND_ADDR>:8080` sends that Host and gets 400, and the
   documented settings in `.env.example`/ARCHITECTURE are inert. Reproduced without Docker:
   `.handoff/D15.attack_compose_env_probe.py` -> `LAN caller 192.168.1.20, Host 192.168.1.5:8080 -> 400`.
   Fix: pass the three variables in `environment:` (as `${NORM_BIND_ADDR}`, `${NORM_ALLOWED_HOSTS:-}`,
   `${NORM_ALLOWED_NETWORKS:-}`) and add a compose test for it.
2. **Three wiring points have no test.** Mutation on a scratch copy (harness: the three D15 test files
   + `test_connector_schema.py`): removing `resolve_and_check` from `build_source_connector`, from
   `build_destination_writer`, or from `create_connection` leaves all 165 tests green. Also green:
   ClickHouse `host=hostaddr or host` reverted in both connectors, the numeric-last-label guard
   removed, and the `ip.version == net.version` check dropped. Killed by tests: CGNAT in built-in set,
   no caller middleware, no TrustedHost, only first DNS answer checked, bad env skipped, `hostaddr`
   dropped from the DSN, mapped address not unwrapped, hostname returned instead of the IP.
   `.handoff/D15.attack_wiring_probe.py` is a ready-made failing-if-removed check.
3. **Password or database name containing `://` breaks the connection.** `engine_from_dsn` tests
   `"://" in dsn`; `build_postgres_dsn("127.0.0.1",5432,"u","pa://ss","db",hostaddr=...)` is a libpq
   string, so it is mistaken for a URL and SQLAlchemy raises `ArgumentError`. Not a bypass; the
   report's fix 5 wants every password character to survive. Fix: test the prefix
   (`startswith(("postgresql://","postgresql+psycopg://"))`). Reproduced in `D15.attack_probe.py`.
4. **`[::1]` in the Host allowlist never matches** (Starlette `TrustedHostMiddleware` splits the Host
   on the first `:`, giving `[`): `Host: [::1]` and `[::1]:8000` -> 400, though ADR/ARCHITECTURE say it
   is always allowed. Refusal side only, no bypass. Fix the claim or the check.

## Low / notes (not blocking)
- `Host: localhost:80@evil.com` -> 200 (same split). A browser cannot send it and a non-browser can
  already send `localhost`; the DNS-rebinding defence holds. Duplicate Host headers: first wins.
- uvicorn trusts `X-Forwarded-For` from 127.0.0.1 (default `--proxy-headers`), so the middleware sees
  the rewritten client there, contrary to ADR "ignored". Only loopback can do it and loopback is
  allowed; a public XFF from loopback is refused. Consider `--no-proxy-headers` in the Dockerfile CMD.
- A bad `NORM_ALLOWED_NETWORKS` makes every request a 500 (fail closed). Acceptable; say so in the docs.

## Implemented, unverified (needs the live stack)
- Docker publish on the LAN address only, source IP preserved for LAN callers (no userland proxy),
  Docker Engine >= 28.3.3 behaviour for loopback-published ports.
- libpq `hostaddr` with a real server and with a real multi-address DNS name; ClickHouse
  `server_host_name` with a real server (ADR says unproven).
- HEALTHCHECK `curl localhost:8080/health` passing with the Host check (Host `localhost`, peer
  127.0.0.1: expected yes, not run in a container).
- UI to API access from a browser on the LAN (CORS list, Host header).
- `test_compose_checker_fails_on_the_pre_change_file` needs full git history (fails in a
  `git archive` copy; passes in the repo).
