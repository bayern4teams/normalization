# D4 report: disguised missing data (native detector)

## Changed
- NEW `packages/normanalysis/src/normanalysis/disguised_missing.py` (113 lines). Nothing else touched; `type_detection.py` NOT modified (no hook needed), no pyproject/uv.lock.
- API: `detect_disguised_missing(value_counts, semantic_type, context=None, *, registry=None, sentinels=None) -> list[DisguisedMissing(value, count, hint)]` (frozen). The two kw-only extras are optional (injection for tests / callers that already hold a registry); defaults are built lazily and cached (`_defaults`).
- Rule (all derived, no numeric constants, no sentinel list): type must have a validator that can say no (`type_detection._discriminates`, reused), FREE_TEXT/UNKNOWN abstain explicitly; reported = values the real normalizer's `validate` rejects, that recur (count > 1), and only if failing cells are a minority of cells (`failing >= valid` -> []). Verbatim values (no strip/casefold merge), sorted (-count, value), count<=0 and non-str keys skipped, input never mutated.
- `hint`: `missing-values.common` via `normalizers.generic_text.load_missing_value_sentinels` (lookup strip+casefold, like the Dispatcher), None if absent.
- `ponytail:` comment names the -999 magic-number ceiling and ptype (pandas 3 / greenery 4) as the upgrade path.
- Registry/loader are imported lazily from `normapi.app` (normapi depends on normanalysis; a top-level import would be a cycle). Uses `normapi.app._DEFAULT_DICTIONARIES_DIR` (private name; one default-resolution copy, as build_normalizer_registry's docstring wants).
