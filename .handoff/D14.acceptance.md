## Notes for the lead (decisions and things I could not derive)

1. **Writer-from-source check passes today.** At HEAD both `build_destination_writer(dest_conn)` calls
   pass `dest_conn`, built from `job["destination_connection_id"]`; in-place reached the source one
   step earlier, where the job is created (the `destination_connection_id` assignment). So the failing
   structural test is `test_no_destination_variable_is_derived_from_a_source`; the writer-call test is
   the permanent guard for the shape the plan describes.
2. **Allowances in the text grep (read at HEAD, different meaning):** `replaced in place (decision #7)`
   (DDL), `in place of` (also when it wraps over two lines, `store.py`), `object in place`,
   `never mutated in place` (`normcore/rules.py`), `across one chunk, in place`, `replicates schema in
   place`. One more allowance: the sentence "the schema refuses an `in_place` field" in
   ARCHITECTURE.md (line 306 at the time of writing), the same words as ADR-013 and ADR-017. ADRs are
   outside the scan. If the lead prefers the plan text literally ("`grep -rn in_place` returns nothing"),
   delete the `REFUSAL_SENTENCE` allowance and reword that cell.
3. **A hand-written refusal mentions `in_place`.** The working tree (mid-implementation, not read in
   detail) has a validator `_refuse_in_place` in `schemas.py` that names the field. That fails the plan 9
   grep and the "no `in_place` validator" check. Setting `model_config = ConfigDict(extra="forbid")` on
   `CloneJobCreateRequest` needs no mention of the name and satisfies the `extra_forbidden` assertion. This
   also refuses every other unknown field on that request; the report does not say whether that is
   wanted (the task said "at least for this field"). Not tested for other fields.
4. **Same-origin refusal (check 4): the layer is not derivable.** No current validation refuses it (HEAD
   has none; 500 from the connect attempt). The ADR text says "every clone writes a separate copy"; I took
   "same connection id and same database name" as the provable case. Any of 400, 409, 422 passes. Identity
   across two different saved connections that point at one server is not decidable here and is not
   tested as a refusal (never guess).
5. **"Empty-destination case" is my reading** of the report line "the empty-destination case in
   `CloneJobCreateRequest`": the `""` defaults go and the fields become required.
